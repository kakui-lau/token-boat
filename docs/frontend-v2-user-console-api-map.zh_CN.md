# Frontend V2 User Console API 映射

> 状态：Live Adapter 已编码，并已通过本地 PostgreSQL 快照、独立 Go API/Redis 和一次真实上游调用的端到端 Smoke；密码、2FA、Passkey、OAuth、注册、邮箱验证码和密码找回接口已接入，重置邮件与 OAuth Auth Flow 已兼容 `/console` 隔离路径，尚未授权切换现网；支付 Sandbox、OAuth Provider 实际回调注册及缺失领域接口仍需继续验证和补齐。

## 1. 运行模式

User Console 页面只依赖 `ConsoleRepository`，有两个实现：

| 模式 | 开启方式                            | 数据来源                                               | 用途                                 |
| ---- | ----------------------------------- | ------------------------------------------------------ | ------------------------------------ |
| Demo | 默认，`VITE_CONSOLE_DATA_MODE=demo` | 浏览器进程内可变数据                                   | UI 开发、评审、组件测试，不调用后端  |
| Live | `VITE_CONSOLE_DATA_MODE=live`       | `VITE_CONSOLE_API_BASE_URL` 指向的 Go 服务；为空时同源 | 隔离环境契约联调，不代表允许生产切换 |

Access Token 只保存在 API Client 闭包内存中，不写入 localStorage。Refresh 和业务请求始终使用 `credentials: include`；现有 Refresh Cookie 继续由 Go 服务管理。

## 3. 联调前必须确认

1. 额度、消费和套餐金额的后端单位，统一转换为展示货币，禁止直接把 quota 整数当 USD。
2. `/api/log/self/usage` 已提供时间序列、按模型聚合、精确平均延迟和成功率；发布前需使用脱敏生产规模数据验证 PostgreSQL/MySQL/SQLite 和可选 ClickHouse 的聚合性能与索引命中。
3. 账户内 2FA/Passkey 管理与登录 `require_2fa`、Passkey begin/finish 已按现有协议接入；隔离环境已完成自动化契约验证，但当前本地后端关闭 Passkey，仍需在启用正确 RP ID/Origin 的环境完成浏览器实机验证。注册、邮箱验证码和找回密码页面已完成；重置邮件通过严格白名单的 `redirect_path` 兼容 `/console/user/reset` 且保留旧路径默认值。OAuth 已完成 Auth Flow 绑定的双路径协议；联调前必须在各 Provider 应用中额外登记 `${server_address}/console/oauth/:provider`，并确保隔离环境 `server_address` 指向浏览器实际访问的 V2 Origin，不能复用生产 OAuth 应用或生产 Client Secret。
4. API Key 创建响应已返回原始 `key` 并由 V2 一次性展示；继续通过回归测试确保列表、搜索、详情和编辑接口只返回掩码，服务端后续响应不得回传明文。
5. Task 不同平台的状态枚举、进度、完成时间和费用单位。
6. 充值与套餐购买接口已接入；隔离环境继续确认各支付 Sandbox 的回跳、Webhook 延迟与重复通知。Creem/Waffo Pancake 需在支付产品侧配置 V2 Success URL；发票下载仍需新增契约。
7. `/api/user/setting` 已提供不含 Secret 明文的读取契约并采用合并更新；隔离环境继续验证 Redis 用户缓存同步及旧前端兼容性。
8. Live Refresh 已完成网络错误、401 和服务不可用分流；多标签页登录/退出已通过不含凭据的 BroadcastChannel/Storage 事件同步，接收端使用 HttpOnly Refresh Cookie 获取自己的访问令牌。隔离环境仍需验证 Cookie Origin Guard、真实 Refresh 轮换和会话撤销后的多标签响应。
9. API Key、请求日志、异步任务和账单交易已完成服务器分页、筛选、排序和最大 100 条 page size；后续新增列表继续复用同一契约，禁止固定抓取前 100 条后在浏览器分页。
10. `/api/pricing` 需要返回当前用户最终销售价格、计费单位、上下文窗口、能力与 availability；用户端禁止收到采购价和渠道成本。
11. 请求日志需要稳定返回 `request_id`、endpoint、token_name、status_code、prompt/completion token、latency、final charge 与脱敏错误信息。
12. Team/Alerts 已在 Live 模式移除本地假邀请、假规则与假开关；新增用户工作区与告警求值 API 前，只允许展示现有个人工作区、Uptime Kuma 状态和余额通知设置。
13. 所有时间型聚合和列表 API 统一支持闭区间开始/结束时间、服务器时区说明和最大查询跨度；快捷范围只在前端生成，自定义范围与快捷范围走同一查询契约。

## 4. 切换边界

在上述契约和 E2E 未通过前，不修改 `web/`、`web/dist/`、`main.go`、Dockerfile 或 release workflow，也不切换现有前端入口。允许为 V2 增加向后兼容的新 API 路由或响应字段，但必须带回归测试且不得改变旧客户端语义。Live 联调固定使用 `token_boat_frontend_v2` PostgreSQL 快照、独立端口与 Redis；快照脚本拒绝覆盖已有数据库，真实上游调用只写快照且可能产生供应商成本。正式切换仍按开发总方案中的影子发布、灰度和一键回滚执行。

## 5. 自动化契约状态

当前 MSW 契约测试覆盖：

- Refresh 401 返回未登录，503 不清除会话；
- `/api/log/self/usage` 的真实字段名、时间范围、服务端每日/模型聚合、精确平均延迟和 quota → USD 换算；
- `/api/log/self/detail/:request_id` 的账户隔离、内部字段清理和深链接独立加载；
- `/api/token/` 分页结构、列表掩码和创建后一次性 Secret；
- API Key 名称/状态/排序分页，请求日志日期/字段/状态/排序分页，任务类型/聚合状态分页，以及账单订单/类型/状态分页；
- `/api/user/setting` 的安全读取、四种通知渠道、quota ↔ USD 换算和无损保存；
- `/api/user/passkey`、`/api/user/2fa/status` 与登录会话状态映射；
- 2FA setup/enable 的二维码、恢复码、验证码和认证轮换；
- Passkey 注册时的 2FA scope proof、浏览器 credential 序列化，以及 assertion step-up 后的解绑；
- 套餐可用支付方式、当前/历史订阅、购买次数与余额额度换算；
- Epay 套餐 POST Form、订单号追踪、充值订单状态确认和临时错误重试；
- Playground 所选 API Key、Group、模型和完整对话请求体；
- 模型目录按当前账户分组映射结构化销售价、URL 筛选恢复，以及带模型参数进入 Playground 后选择兼容 API Key；
- 登录能力开关、密码登录的 2FA challenge、备用码验证、Passkey discoverable credential 序列化与 Session Bundle 建立；
- GitHub、Discord、OIDC、Linux DO 和自定义 OAuth Provider 能力映射，`client=console_v2` State、服务端返回的绑定回调、Authorization URL 协议限制、回调交换和 Session Bundle 建立；
- 注册开关、邮箱验证/Turnstile 参数、邀请码、密码找回请求和一次性新密码返回；组件测试覆盖注册提交、防账户枚举提示、无效重置链接和确认后的一次性密码展示；
- 充值配置、报价、余额购买、余额不足和支付回跳状态由组件与共享 MSW 契约共同覆盖。

这些测试用于固定前后端已确认契约，不能替代隔离 Go 服务、数据库、Redis、Cookie 和支付 Sandbox 的端到端验证。
